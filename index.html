SkinSight

Java (Android) · Python · TensorFlow / Keras · TensorFlow Lite · lead of a team of three, corresponding author

An Android app that screens for skin cancer from a photo, built for people who cannot easily reach a dermatologist. I compared four kinds of neural network, shipped the best one on the phone itself, and published the result.

  • Measured before choosing. Four model types, three trials each, on the same skin-lesion images.
  • Trained every layer, not only the last. Trainable parameters went from about 5,000 to more than 6 million.
  • Picked the model by validation loss. Of four EfficientNet-Lite variants, Lite3 was best, stopped at 32 epochs before it began to overfit.
  • Treated skin-tone bias as a design requirement, because models trained mostly on light skin do worse on darker skin.

WinnieWheels

C++ (Arduino) · Node.js / Express · React · Raspberry Pi · Software Chair, Women in ECE

An autonomous delivery robot with a live web control interface, built over two semesters. It ran both days of Engineering Open House, where hundreds of visitors drove it. I designed the architecture, wrote the hardware interface, and led the software team.

  • Noisy sensors. One bad ultrasonic reading made the robot brake for nothing. I moved to a three-sample read that rejects out-of-range and timed-out values.
  • A saturated serial link. The navigation loop re-sent the same command every cycle. Now a command is sent only when the decision changes.
  • Left-right oscillation. With two sensors, which way to turn is ambiguous. The robot turns away from the closer obstacle and uses one default direction when the readings are within 4 cm.
  • A simulator on the same code path. We had more people than robots, so every member could run the full stack on a laptop with no hardware.

NetWatch

Python · Claude API · GitHub Actions · pytest

A log-triage agent for network devices, built so that the evaluation decides whether a change can merge. The language model explains an alert; it never decides that there is one.

  • Every model call is measured for latency, tokens and cost, so a regression shows up as a number.

Genome sequencing pipeline

Linux cluster on Google Cloud · bwa · samtools · ANNOVAR · UChicago Summer Immersion, team of three

A four-stage pipeline that compares a person's DNA with a reference genome and narrows more than 200,000 differences down to the few that could cause disease. We traced one to BBS2, a gene linked to a rare disorder that affects vision.

  • Parallel by design. A head node sends each job to worker nodes; the number of workers and threads per node are the tuning levers.
  • Found the bottleneck first. Alignment and annotation took most of the run time.
  • Scaled 23 times for 8 times the cost. One chromosome took 2 hours and $18.75; all 23 took 16 hours and $150.

Decoding Bias

Python · Beautiful Soup · NLTK · spaCy · VADER · UCSB Summer Research Academies, published co-author

A study of how the 50 most-viewed news outlets write about people with disabilities. I owned keyword engineering and pipeline optimization for a scraper that collected more than 14,000 articles.

  • A two-stage pipeline. A retriever collects article links; a scraper downloads, parses and splits each article into sentences.
  • I designed the 71-keyword lexicon that decides which sentences enter the sample.
  • "Capable" is a grammar test. Is the person the subject of the sentence or its object? Dependency parsing answers that for every sentence.

Crisis Management App

Java (Android) · Firebase · transfer learning · team of two, 2022

An app that connects people donating supplies after a disaster with people who need them, in real time. A photo of an item is sorted into one of seven categories automatically, and one tap texts your location to your emergency contacts.

  • Six phone and Google services in one app: Contacts, Location Services, SMS, Camera, Google Maps and charting, on a Firebase database shared by every user.
  • Better data before more training. Accuracy rose from 66% to 86% by adding full-size photos, then to 89% by stopping at 33 epochs, before overfitting.
  • The model suggests; the user decides. The predicted category is pre-selected and can be overridden.
